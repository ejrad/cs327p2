5. (3 points) For the ciphertext in the last question, how will Bob decrypt it?

Bob computes m2 = c^d mod N, with c from Q4, d from Q3 and N from Q1
(c.modPow(d, N), square-and-multiply over the 3070 bits of d).

m2 = 0x3, equal to m, so encryption and decryption are consistent.

6. (3 points) Measure the speed of RSA decryption by running it 1000 times.

The program times 1000 decryptions with System.currentTimeMillis() (after one
warm-up call) and uses speed = bit size of N / (total seconds / 1000).

1000 decryptions:     18773 ms
Time per decryption:  18.773 / 1000 = 0.018773 s
Speed:                3072 / 0.018773 = 163,639 bps = 163.639 kbps
In Gbps:              0.000163639 Gbps

Is this good enough for gigabit Internet? No. 1 Gbps = 1,000,000 kbps, so a dedicated
decrypting device at 163.639 kbps would be about 6,100 times too slow and would
become the bottleneck.

Is CRT four times faster? Almost: 646.329 / 163.639 = 3.95 times faster in my run,
just under 4. In theory each CRT exponentiation uses a modulus and exponent half as
long, so it costs about 1/8 of a full one; two of them cost 1/4, a 4x speedup. CRT
falls slightly short because it adds fixed extra work that plain RSA does not have
(reducing c mod p and mod q, and the recombination multiply and mod), and because
Java's BigInteger uses faster multiplication algorithms (Karatsuba/Toom-Cook) for
large numbers, so halving the size saves a little less than the simple model predicts.
Timer and JIT noise also shift the ratio slightly between runs. Even with CRT,
decryption is still about 1,500 times too slow for 1 Gbps Internet.
